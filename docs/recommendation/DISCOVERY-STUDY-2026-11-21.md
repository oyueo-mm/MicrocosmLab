# 추천 전략 10종 — 운영·실험 구분과 평가 설계 (2026-11-21)

> **중요:** 사용자 간 상호작용/서버 집계 데이터가 아직 없다. 콘텐츠 기반·편집자 신호·발견형·사용자 선택 기반 추천은 구현/비교 가능하지만, 실제 **인기·협업 필터링 성능**은 학습/검증할 수 없다. **V3를 운영 기본값으로 보존**한다.

## 사용자 대상 기능

- 홈의 **추천 설정**을 열면 관심 주제를 선택할 수 있다. 설정은 선택사항이고 기본 화면을 가리지 않는다. 기존 `microcosmlab-preferences-v1`의 동일 키 안에 `topics`를 저장해 과거 좋아요·숨김을 보존한다.
- 같은 패널에서 **기본 V3 / 탐색 실험**을 전환할 수 있다. 탭 새로고침 후에는 안전하게 기본 V3가 적용된다. 탐색 실험은 기존 V3 개인화 후보를 일부 보존하면서 포식·방어 같은 주요 영상의 검수 상태/명시 흥미도, 새로운 생물, 카테고리·제작자 분산에 가중치를 둔다. **실제 만족도가 높다고 검증한 것은 아님**.
- **추천 평가**: `#/recommendation-study`에서 기준 영상과 추천 후보 영상을 둘 다 직접 재생하고, **내용 관련성(0~3)**과 **다음 시청 의향(0~3)**을 독립적으로 표시. 연구 후보의 알고리즘 출처는 UI에서 숨긴다. 재생 불가/판단 불가를 **0점이 아닌 결측**으로 다룬다.
- 평가 데이터는 브라우저 `localStorage`에만 저장되며, 사용자가 **평가 내보내기**를 눌렀을 때만 JSON으로 다운로드된다. 로그인/서버 업로드/실사용자 공유 통계는 없음. 사용자에게 자동 연구 참여 동의를 받은 것으로 가정하지 않는다.

## 편향에 강한 평가 원칙

1. 예전 42개 **동일 생물종·동일 카테고리 기반 NDCG**는 메타데이터 일치 대리 지표이다. KNN의 특징과 정답 정의가 겹치므로 **실제 사용자의 선호 NDCG로 해석 금지**.
2. 연구용 블라인드 Pool은 **V3, TF-IDF, BM25, 콘텐츠 KNN, Hybrid, MMR, 무작위 후보**를 혼합하고 중복을 제거한 뒤 출처 알고리즘을 가리고 제시한다. 정적 결정론적 풀로 테스트 재현성 확보. 영상 재생은 Commons 허용 자료에 한정. 시리즈/메타데이터 오염 가능성은 별도 검수한다.
3. **미평가/재생 불가 후보는 오답으로 채우지 않는다.** `src/recommendationJudgments.ts`의 `evaluateHumanJudgments`는 주어진 후보의 판단 커버리지가 부족한 경우 점수를 `null`로 반환한다. Pool 기반의 불완전 판단과 사용자/장면 관련성 평가의 한계를 보고한다.
4. 각 기준 영상에 대해 **6개 추천기의 Commons 재생 후보 상위 3개씩을 우선 Pool에 포함**하고 무작위 후보 등으로 22개까지 확장해 블라인드 순서로 제공한다(기본 10개 기준 영상 × 22개 = 220개 영상 쌍). 실제 평가 점수가 존재할 때만 각 모델의 **nDCG@3**를 산출한다. 중복 후보는 공유되며 평가 편향·부분 판단의 한계는 계속 명시한다.
5. 테스트에 쓴 사례를 모델 가중치 튜닝에 사용한 뒤 독립 홀드아웃으로 주장하지 않는다. 실제 평가 데이터를 확보하면 **훈련/개발/독립 평가**를 분리하고 평가자 간 일치도, 카테고리·원본 제작자 층화, 노출·선택 편향을 검토한다.
6. 인기 기반은 **노출(분모)** 없는 좋아요 합계를 인기도라고 주장하지 않는다. `estimatePopularity`는 실제 노출이 최소 기준을 넘은 **참여 동의 기반** 데이터에만 쓰도록 설계했고, 현재 배포 사이트는 해당 데이터를 확보하지 못한다.
7. 품질 점수는 `qualityRank`의 **기존 메타데이터 기반 추정**으로, 재생 품질·장면 흥미도·생물학적 동정에 대한 독립 현장 검수가 아니다. 상단에 노출한다고 해서 '실제 장면 검수 완료'라는 문구를 추가하지 않는다.

## 코드 / 실행 / 테스트

- `src/recommendationDiscovery.ts`: 편집자/품질 우선, 신규 대상 탐색, 분산 랭킹, 인기 추정 연구 함수.
- `src/RecommendationControls.tsx`: 자발적 관심 분야 선택, 기본 V3/실험형 전환, 평가 진입.
- `src/recommendationV3.ts` 및 `src/usePreferences.ts`: 9가지 관심 주제 신호를 기존 로컬 선호에 통합.
- `src/recommendationJudgments.ts`: 알고리즘 혼합 블라인드 후보와 판단 커버리지 검증.
- `src/RecommendationStudy.tsx`: 영상 직접 재생, 관련성/다음 시청 의향 평가 및 수동 다운로드.
- `src/recommendationOnlineLab.ts`: 기존 ItemKNN/그래프 전파/LinUCB 단위 실험.
- `scripts/test-recommendation-discovery.mjs`: 랭킹 일관성/중복/숨김/선택 관심사 효과, 실 인기 미보유, 연구 후보 결정론성, 미평가 점수 누락 점검.
- `node scripts/evaluate-human-judgments.mjs 평가파일.json` (자발적으로 내려받은 로컬 평가 JSON에서 Commons 상위 3개 판단 커버리지 충족 시에만 nDCG@3 보고), `node scripts/test-recommendation-discovery.mjs`, `node scripts/test-recommendation-v3.mjs`, `node scripts/test-recommendation-lab.mjs`, `node scripts/test-online-research-prototypes.mjs`, `npm run build`.

## 검증 결과와 재현성

- PR #15 사전 CI ([실험 실행 #44845008738](https://github.com/oyueo-mm/MicrocosmLab/actions/runs/44845008738)): **대표 카탈로그 1,196개**, 테스트 평가 풀 **8개 시드 × 22개 후보 = 176쌍**, 선택 관심사 반영 확인, 숨김 누출·중복 0, 빈 사람 평가셋 결과 null 등 검사. **실제 사람 평가 수치는 없음.**
- 기본 연구 UI는 **10개 시드 × 22개 후보 = 220쌍**(현재 카탈로그가 바뀌지 않을 경우). 완전한 판단이 모여야 모델별 상위 3개 Commons 영상에 대한 nDCG@3를 계산할 수 있다.
- 내보내기 JSON에는 `poolId` 지문을 기록하고, CLI 평가 시 현재 카탈로그와 후보 풀의 지문이 다르면 **실패**하도록 함. 향후 데이터가 바뀌면 과거 평가와 다른 카탈로그 기준의 결과를 몰래 결합하지 않는다. 빈/미평가 점수를 0점으로 대체하지 않는다.
- 브라우저별 실제 플레이어 동작과 전 영상의 재생 성공은 CI 타입 검사만으로 입증되지 않으며 수동 실기기 검증이 필요하다.

## 다음 단계

- 사람 평가용 영상 풀에 **독립 평가자 2명 이상**의 실제 판단을 확보하고, 고르지 않은 영상의 불확실성을 표시하며 평가자 간 일치도를 확인한다.
- 실제 사용자에게 선택적 동의와 삭제가 가능한 데이터 수집 API를 별도 설계하기 전까지 **개인 선호를 서버로 전송하지 않는다**.
- 연구용 임베딩은 실제 산출했지만 사이트 동영상 추천의 기본값으로 사용하지 않는다. 관련성이 독립적으로 평가된 후, 브라우저 성능 및 정적 파일 비용을 검증한 뒤 배포 가능 여부를 결정한다.
- 일정한 트래픽/동의 데이터가 생겼다면 인기 기반, ItemKNN, 학습 LightGCN, LinUCB를 별도 로그와 함께 검증한다.
